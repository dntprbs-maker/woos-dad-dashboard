> 이 페이지가 Notion 작업관리 규칙의 Single Source of Truth입니다. AI별 프롬프트나 각 저장소에 같은 규칙을 복사해 두지 않습니다.
> 변경은 아빠의 명시적인 지시가 있을 때만 합니다. AI는 스스로의 판단으로 이 페이지를 고치지 않습니다.
## 운영규칙
1. 작업의 최종 원장은 Notion 작업·업무협업 DB다.
2. 신규 작업 생성 전에 반드시 기존 작업을 검색한다.
3. 동일하거나 유사한 작업이 있으면 새 작업을 만들지 않고 기존 작업을 갱신한다.
4. 중복 후보가 발견되면 강제로 신규 생성하지 않는다.
5. 미완료 작업 조회는 서버측 조건으로 미완료 작업만 조회한다.
6. 완료 작업이 필요하면 필요한 기간만 조건 조회한다.
7. 작업 완료 시 상태, 완료 내용 및 필요한 검증 결과를 원장에 기록한다.
8. 작업 세션 종료 전 다음 내용을 확인하고 원장에 반영한다. 오늘 완료한 작업 / 진행 중인 작업과 현재 상태 / 새로 발견한 문제 / 미해결 문제 / 아빠의 결정이 필요한 사항 / 다음에 해야 할 작업 / 관련 Git Commit / 중요 관련 파일
9. 저장소의 TODO.md 는 보조 기록이며 Notion 작업·업무협업 DB를 대체하지 않는다.
10. 코드는 Git/GitHub에 기록하고 작업 상태와 미해결 사항은 Notion 작업 원장에 기록한다.
11. 메모리 허브 관련 작업의 프로젝트 구분은 기존 명칭인 master-project 를 계속 사용한다.
12. 여러 프로젝트 전체에 관련된 공통 작업도 master-project 로 분류한다.
13. 아직 별도 프로젝트로 등록되지 않은 프로그램이나 미분류 작업도 master-project 로 분류한다.
14. 기존 프로젝트명은 특별한 이유가 없으면 일괄 변경하지 않는다.
15. 노션 운영규칙 자체는 아빠의 명시적인 지시가 있을 때만 변경한다.
## 읽고 쓰는 방법
- 작업관리 관련 작업을 시작하기 전에 MCP 도구 get_notion_rules를 호출해 최신 규칙을 확인한다.
- 변경은 update_notion_rules로 하되, 아빠의 명시적 지시가 있을 때만 쓴다.
- MCP: 공용 작업관리 (https://woos-dad-dashboard.vercel.app/api/mcp)
- REST: GET /api/v1/rules, PATCH /api/v1/rules
